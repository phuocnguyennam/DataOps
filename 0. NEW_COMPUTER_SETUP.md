## Prerequisites

**📌 Operating System:**  
This guide is written for **Windows 10/11 only**. All commands are run in **PowerShell** (or Windows Terminal) and use Docker Desktop with the WSL2 backend.

### Required Software

1. **Docker Desktop for Windows**
   - Download from [Docker Desktop for Windows](https://www.docker.com/products/docker-desktop)
   - Enable the **WSL2 backend** during installation (default)
   - Install and start Docker Desktop
   - Ensure Docker is running (whale icon in the system tray)

2. **Terminal**
   - **PowerShell** or **Windows Terminal** (built into Windows)
   - Open the terminal in the project folder (right-click the folder → *Open in Terminal*)

3. **Visual Studio Code** with the **SQL Server (mssql)** extension
   - Download VS Code: https://code.visualstudio.com/
   - Install the extension: open Extensions (`Ctrl+Shift+X`), search for **SQL Server (mssql)** (publisher: Microsoft, ID `ms-mssql.mssql`), and click *Install*

## Step 1: Start Services

**Note:** Run all commands in PowerShell from the project folder.

1. **Build and start containers:**
```bash
# Build containers (first time only, or after changes)
docker-compose build --no-cache

# Start all services in background
docker-compose up -d
```

2. **Wait for services to start** (about 1-2 minutes)

**Verify services are starting:**
```bash
# Check container status
docker-compose ps

# Watch logs (optional)
docker-compose logs -f
```

Press `Ctrl+C` to stop watching logs.

## Step 2: Initialize Database

**Note:** Run these commands in PowerShell from the project folder.

**Run database restore:**
```bash
docker-compose exec sqlserver /tmp/restore_db.sh
```

**What this does:**
- Restores the AdventureWorks2014 database inside the SQL Server container
- Creates sample data for your pipeline

**Verify database was restored:**
```bash
docker-compose exec sqlserver /opt/mssql-tools/bin/sqlcmd -S localhost -U sa -P "YourStrong@Passw0rd" -Q "SELECT name FROM sys.databases"
```

You should see `AdventureWorks2014` in the list.

## Step 3: Set Up DBT

**Note:** All DBT commands are executed inside the dbt container.

1. **Install DBT dependencies:**
```bash
docker-compose exec dbt dbt deps
```

2. **Create a SQL Server user for DBT:**
```bash
# View existing users
docker-compose exec sqlserver /opt/mssql-tools/bin/sqlcmd -S localhost -U sa -P "YourStrong@Passw0rd" -Q "SELECT name FROM sys.sql_logins WHERE type = 'S';"

# Create new user with db_owner role
docker-compose exec sqlserver /opt/mssql-tools/bin/sqlcmd -S localhost -U sa -P "YourStrong@Passw0rd" -Q "CREATE LOGIN imrandbtnew WITH PASSWORD = 'Imran@12345'; USE AdventureWorks2014; CREATE USER imrandbtnew FOR LOGIN imrandbtnew; ALTER ROLE db_owner ADD MEMBER imrandbtnew;"
```

3. **Verify DBT connection:**
```bash
docker-compose exec dbt dbt debug
```

**Expected output:**
- All connection checks should show `OK`
- If any checks fail, review the error messages

## Step 4: Set Up Airflow

**Note:** All Airflow commands run inside containers.

1. **Initialize Airflow database:**
```bash
docker-compose exec airflow-webserver airflow db init
```

**What this does:**
- Creates Airflow's metadata database
- Sets up tables for DAGs, tasks, logs, etc.

2. **Create Airflow admin user:**
```bash
docker-compose exec airflow-webserver airflow users create \
  --username admin \
  --firstname Admin \
  --lastname User \
  --role Admin \
  --email admin@example.com \
  --password admin
```

**Credentials to remember:**
- Username: `admin`
- Password: `admin`

**Security Note:** In production, use a strong password!

## Step 5: Verify Setup

1. **Check if all containers are running:**
```bash

```

**Expected output:** All services should show "Up" status:
- sqlserver
- postgres  
- airflow-webserver
- airflow-scheduler

2. **Access Airflow UI:**
   - Open browser: http://localhost:8080

     - Username: `admin`

3. **Test DBT models:**
```bash
docker-compose exec dbt dbt run
```

4. **View data in SQL Server:**

2. Click the **SQL Server** icon in the Activity Bar → **Add Connection**.
3. Enter the connection details below.
4. Right-click the connection → **New Query** to run SQL.

**Connection Details:**
- Server name: `localhost,1433` (comma, not colon!)
- Database name: `AdventureWorks2014`
- Authentication Type: SQL Login

## Common Issues and Solutions

### 1. **Port Conflicts**
If ports 8080, 1433, or 5432 are already in use:

**Check what's using the port:**
```powershell
netstat -ano | findstr :8080
taskkill /PID <process-id> /F

# Or stop the conflicting Docker container
docker ps -a
docker stop <container-name>
```

**Or modify ports in docker-compose.yml**

### 2. **Permission Issues**

```powershell
# Run PowerShell as Administrator
icacls * /reset
icacls * /grant Everyone:F /t
```

Also make sure your Windows user is in the **docker-users** group (Computer Management → Local Users and Groups → Groups → docker-users), then sign out and back in.

### 3. **Database Connection Issues**
Check if SQL Server is running:
```bash
docker-compose ps sqlserver
```

Verify database restore:
```bash
docker-compose exec sqlserver /opt/mssql-tools/bin/sqlcmd -S localhost -U sa -P YourStrong@Passw0rd -Q "SELECT name FROM sys.databases"
```

### 4. **Docker Issues**
If containers won't start:
```bash
docker-compose down -v
docker system prune -a
docker-compose up -d
```

### 5. **Command Not Found Errors**

**"chmod: command not found"**
- Such commands run inside Linux containers, not in PowerShell
- Use the `docker-compose exec ...` commands that execute inside containers

**"docker-compose: command not found"**
- Make sure Docker Desktop is running and restart PowerShell
- Alternatively use `docker compose` (without the hyphen)

### 6. **SQL Server (mssql) Extension Connection**

**Connection Settings:**
- Server name: `localhost,1433` (note the comma, not colon)
- Database name: `AdventureWorks2014`
- Authentication Type: SQL Login
- User name: `imrandbtnew` (or `sa`)
- Password: `Imran@12345` (or `YourStrong@Passw0rd`)
- Trust server certificate: **Yes**

**Extension:** install **SQL Server (mssql)** (`ms-mssql.mssql`) from the VS Code Extensions view.

## Need Help?

If you encounter any issues:

### 1. **Check Container Logs**
```bash
# All services
docker-compose logs

# Specific service
docker-compose logs sqlserver
docker-compose logs dbt
docker-compose logs airflow-webserver

# Follow logs in real-time
docker-compose logs -f
```

### 2. **Verify Each Service**
```bash
# Check SQL Server
docker-compose exec sqlserver /opt/mssql-tools/bin/sqlcmd -S localhost -U sa -P YourStrong@Passw0rd -Q "SELECT @@VERSION"

# Check DBT
docker-compose exec dbt dbt debug

# Check Airflow
docker-compose exec airflow-webserver airflow version
```

### 3. **Common Troubleshooting Commands**
```bash
# Restart a specific service
docker-compose restart sqlserver

# View logs for a specific service
docker-compose logs sqlserver

# Rebuild a specific service
docker-compose build sqlserver

# Stop all services
docker-compose down

# Remove all data and start fresh
docker-compose down -v
docker-compose up -d
```

### 4. **Platform-Specific Issues**

- Make sure virtualization is enabled in BIOS and WSL2 is installed (`wsl --update`)
- Run Docker Desktop as Administrator if permission issues occur
- Check Windows Firewall if connection issues occur
- Check Docker Desktop is running: `docker info`
